# ПОТОК

Прототип цифрового двойника автомобильной отгрузки нефтепродуктов для студенческого хакатона УУНиТ. Отраслевой контекст — «Газпром нефть». Учебная разработка, без связи с действующими системами и без официального одобрения компании.

**Все демонстрационные данные и расценки синтетические.** Расчётный эффект не является фактической экономией предприятия.

## Запуск приложения

Из корня проекта в PowerShell:

```powershell
.\Start-POTOK.ps1
```

Скрипт собирает приложение, подготавливает локальную SQLite/D1 и запускает его на `http://127.0.0.1:5173`. Для остановки — Ctrl+C. Обычный повторный запуск сохраняет историю и не применяет миграции заново. При занятом порте сначала остановите прежний экземпляр или задайте `-Port 5174`.

Демонстрационные аккаунты: **analyst** (расчёты и запись) и **viewer** (просмотр и локальные эксперименты). Пароль обоих: **Potok-2026!**. Это публичные учебные аккаунты.

На этом компьютере зависимости установлены. Для переноса нужны Node.js 24+ и pnpm 11.25.0:

```powershell
cd app
pnpm install --frozen-lockfile
pnpm local
```

Дополнительные команды из корня:

```powershell
.\Start-POTOK.ps1 -PrepareOnly  # сборка и база без запуска сервера
.\Start-POTOK.ps1 -SkipBuild    # запуск существующей актуальной сборки
.\Start-POTOK.ps1 -Dev          # режим разработки с обновлением исходников
```

Рабочая база — `app/.wrangler/state`. Её нельзя удалять при очистке сборочных файлов, если нужно сохранить историю. Для резервной копии остановите приложение и скопируйте эту папку целиком. При переносе также сохраните исходный код и версии зависимостей.

## Что реализовано

Шесть экранов: обзор смены, сценарии, исследование вариантов, связанный с моделью 3D-тур, данные и история. Расчёты выполняются в Web Worker; сохраняемый результат повторно вычисляется сервером. Сценарий, расчёт и аудит записываются атомарно. История позволяет воспроизвести прогон с проверкой хеша данных, версии ядра, seed и всех KPI.

Исследование проверяет 48 конфигураций на 12 seeds, затем выбранную — на 30 других seeds и при сбое поста. Показаны граница Парето, интервалы среднего эффекта и чувствительность к цене ожидания.

**Статус приёмки:** 45 автоматических тестов, TypeScript и production-сборка проходят. Проверена подготовка пустой локальной базы и повторный запуск миграций. Браузерная и визуальная приёмка ещё не пройдены: доступ инструмента к локальному адресу отклонён сохранённой политикой браузера. Проект не объявлен окончательно готовым и не опубликован. Презентация отложена по указанию пользователя до готовности приложения.

## Расчётное ядро и проверки

Требуется Node.js 24+ (проверено на 24.22.1). Для unit-тестов и эталонного эксперимента установка пакетов не нужна.

```powershell
cd app
node --experimental-strip-types --test tests/*.test.ts
node --experimental-strip-types scripts/run-experiment.ts
node --experimental-strip-types scripts/benchmark.ts
pnpm typecheck
```

Эксперимент создаёт `app/outputs/experiments/reference-experiment.json`: базовый расчёт, сетку 48 вариантов, отдельные seeds поиска и проверки, парное сравнение и стресс-сценарий. Основной JSON содержит все исходные параметры и события базовой смены. `synthetic-dataset.json` — воспроизводимый исходный набор.

Фактические результаты эталонного набора 1.1.0: средний SLA базы 12,86%, выбранного варианта 93,17% на 30 проверочных сменах. При двухчасовом отключении одного поста SLA падает до 84,40% — ниже целевых 85%. Это существенная граница решения, а не пройденный тест устойчивости. Расходы условные, без CAPEX; результат не является экономическим обоснованием покупки дополнительных постов.

## Область модели

Регистрация, выпуск партии по качеству, конечный запас, совместимые посты налива, контроль количества и оформление. Дискретно-событийный календарь, устойчивое резервирование продукта, воспроизводимая случайность, интервалы парного эффекта и Парето в исследованной сетке.

Пополнения резервуаров, физика нефтепереработки и реальные ERP/MES/1С не входят в текущую модель. Подробные допущения перечислены в спецификации.
