# ПОТОК

Цифровой двойник участка автомобильной отгрузки нефтепродуктов. Приложение моделирует смену, находит причины ожидания и сравнивает изменения мощности и правил очереди. Состояние терминала можно изучать в интерактивной 3D-сцене.

Проект команды **burmalcode78** для студенческого хакатона УУНиТ 2026. Предметный контекст — «Газпром нефть».

## Возможности

- Расчёт регистрации, допуска партий, налива и оформления с ограниченными ресурсами и конечным запасом.
- Сценарии мощности, совместимости постов, правил очереди и временной недоступности оборудования.
- Сравнение выпуска, выполнения в срок, ожидания, незавершённых заявок и модельных расходов на одинаковом спросе.
- Исследование 48 конфигураций, отдельная проверка выбранного варианта, интервалы парного эффекта и стресс-сценарий.
- 3D-терминал с движением машин, инспектором объектов, журналом, камерами и управлением временем.
- Сохранение расчёта на сервере и повтор из истории с проверкой данных, версии ядра и показателей.

Все демонстрационные данные и расценки синтетические. Результаты относятся к модели участка и требуют калибровки перед применением на реальном объекте.

## Быстрый запуск

Требуются **Node.js 24+** и **pnpm 11.25.0**.

```powershell
git clone https://github.com/code7-8/potok-digital-twin.git
cd potok-digital-twin
cd app
pnpm install --frozen-lockfile
cd ..
.\Start-POTOK.ps1
```

Открыть **http://127.0.0.1:5173**. Скрипт собирает приложение, создаёт локальную базу и запускает сервер. Для остановки — Ctrl+C.

| Аккаунт | Пароль | Доступ |
|---|---|---|
| `analyst` | `Potok-2026!` | Расчёты, импорт, сохранение |
| `viewer` | `Potok-2026!` | Просмотр и локальные эксперименты |

Для запуска из каталога `app` на других платформах: `pnpm local`.

## Демонстрация

Кнопка **«Демонстрация»** открывает четыре шага: базовая смена, причина очереди, изменение мощности и проверка сбоя. Используется выбранный набор данных. Сцена показывает одну смену с seed 42, сравнительная таблица — средние за 30 парных смен.

В разделе **«Сценарии»** можно изменить параметры, выполнить сравнение и сохранить рассчитанную смену. Раздел **«История расчётов»** позволяет открыть сохранённые параметры или воспроизвести результат. В **«3D-туре»** доступны выбор машины и оборудования, перемотка, пауза, ракурсы и режим день/ночь.

## Результаты эталонного эксперимента

Набор версии 1.1.0 содержит 84 заявки и 1 974 т спроса на 12 часов. База использует три поста налива, один ресурс оформления и очередь по прибытию. Выбранная конфигурация использует шесть постов, два оформления и очередь по сроку.

| Показатель | База | Выбранный вариант |
|---|---:|---:|
| Отгружено, т | 1 105,4 | 1 974,0 |
| Выполнено в срок, % | 12,9 | 93,2 |
| Среднее ожидание, мин | 246,9 | 57,4 |
| Модельные расходы, тыс. ₽ | 431,5 | 285,5 |

Средние за 30 проверочных смен на одинаковом спросе. При двухчасовом отключении первого поста средний SLA выбранного варианта составляет 84,4% при целевом уровне 85%. Модель расходов учитывает ресурсы, очереди и обработку; капитальные вложения в расчёт не входят.

## Разработка и проверки

Команды выполняются из `app`:

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm local
```

66 автоматических проверок охватывают модель, эксперименты, API, хранение, воспроизведение и проекцию событий. Для интерфейса и 3D предусмотрены 13 сценариев Playwright:

```powershell
pnpm exec playwright install chromium
pnpm test:browser
```

Эталонный эксперимент и нагрузочный стенд:

```powershell
node --experimental-strip-types scripts/run-experiment.ts
node --experimental-strip-types scripts/benchmark.ts
```

Результаты эксперимента создаются в `app/outputs/experiments/`. Рабочая локальная база хранится в `app/.wrangler/state`; повторный запуск сохраняет историю.
