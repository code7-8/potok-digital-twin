# Архитектурные решения

## Модель процесса

Для участка отгрузки выбрана дискретно-событийная модель. Состояние меняется при прибытии, начале и завершении операций, выпуске партии и недоступности поста. Такой подход сохраняет точные временные границы операций и позволяет проверять очереди, занятость ресурсов и баланс продукта.

Ядро реализовано как чистая функция с типизированными входами, сценарием и seed. Оно используется в браузерном Worker, серверных расчётах и экспериментальном стенде.

## Технологии

TypeScript объединяет расчётное ядро и веб-часть. React/Vinext используется для интерфейса и серверных маршрутов. D1/SQLite хранит пользователей, сессии, наборы данных, сценарии, расчёты и аудит. Three.js отображает состояние терминала, Recharts — результаты расчётов.

Версии зависимостей зафиксированы lock-файлом. Для запуска используются Node.js 24+ и pnpm 11.25.0.

## Сравнение сценариев

Спрос фиксируется между альтернативами. Случайные длительности привязаны к seed, ID заявки и операции, поэтому смена порядка обслуживания сохраняет сопоставимость возмущений. Поиск и проверка выбранного варианта используют разные seeds.

Выбор производится в конечной сетке конфигураций по среднему SLA и модельным расходам. Отдельно рассчитываются интервалы среднего эффекта, разброс смен и одинаковый сбой в обоих вариантах.

## Сохранение

Перед записью сервер повторяет расчёт на сохранённом наборе. Сценарий, результат и две записи аудита фиксируются одной транзакцией. Повтор из истории проверяет хеш данных, версию ядра, seed и сохранённые KPI.

## Визуализация

3D получает результат того же расчёта и выбранное время. Идентификаторы ресурсов и резервуаров связывают объекты сцены с данными. Траектории транспорта условные; они не изменяют расчётные интервалы операций.
