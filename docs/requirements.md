# Требования и трассировка приёмки

Источник задания: «Презентация 2х хакатон (1).pptx», 12 слайдов. Срок пользователя: 9 ноября 23:00. Таблица ниже разделяет обязательные условия и предложенные усиления. Статус отражает проверяемый результат, не намерение.

## Бизнес-требования

Фактические результаты приёмки и соответствующие тесты: [acceptance.md](acceptance.md). Наличие функции или тестового сценария не означает завершённую браузерную приёмку.

| ID | Требование | Критерий |
|---|---|---|
| BR-01 | Аналитик сравнивает изменения до внедрения | Из одного набора спроса получает базу и альтернативу с явными параметрами |
| BR-02 | Руководитель понимает причину задержки | Ожидание разделено по регистрации, запасу/допуску, наливу и оформлению |
| BR-03 | Решение не скрывает неопределённость | Интервалы среднего эффекта, разброс смен и ограничения модели подписаны раздельно |
| BR-04 | Аудит результата | По сохранённому набору, сценарию, seed и версии ядра можно повторить расчёт |
| BR-05 | Посетитель понимает производственный процесс | Точки 3D-тура связаны с процессом, кейсом и вычисленной метрикой |

## Функциональные требования

| ID | Требование | Проверка / ожидаемый результат | Основание |
|---|---|---|---|
| FR-01 | Загрузка синтетического набора и проверка структуры | Ошибки ID, единиц, диапазонов, ссылок и вместимости возвращаются явно | слайды 8, 11, 12 |
| FR-02 | Воспроизводимый запуск модели | Те же входы и seed дают идентичные события и метрики | слайд 8 |
| FR-03 | Ограничение ресурса и совместимости | На посту одновременно ≤1 машины; несовместимые продукты не назначаются | слайд 8 |
| FR-04 | Допуск партии и материальный баланс | Налив после выпуска; невязка массы ≤1e-7 т | предложенное усиление |
| FR-05 | Сценарии и сравнение | Сохранить альтернативу, перезапустить, увидеть разности показателей | слайды 8, 10 |
| FR-06 | Учет горизонта и незавершённых | Все заявки учтены; выпуск только внутри смены | корректность метрик |
| FR-07 | Поиск узких мест | Показать ожидание по причинам и загрузку ресурсов, а не заранее заданный текст | слайды 8, 10 |
| FR-08 | Статистические эксперименты | Парные seeds; 95% CI среднего эффекта; отдельный набор проверки | предложенное усиление |
| FR-09 | Исследование вариантов | Отображается граница Парето конкретной сетки и явное правило выбора | предложенное усиление |
| FR-10 | Стресс-сценарий | Недоступность поста меняет календарь, загрузку и итог; баланс сохраняется | предложенное усиление |
| FR-11 | Дашборд | Цикл, выпуск, загрузка, стоимость с единицами, знаменателями и детализацией | слайды 8, 10 |
| FR-12 | Авторизация | Неавторизованный запрос к данным отклоняется, выход завершает сессию | слайд 12 |
| FR-13 | Разделение ролей | Аналитик сохраняет сценарии, наблюдатель читает; сервер проверяет право | проектное решение |
| FR-14 | Постоянное хранение | Сценарий доступен после перезапуска и новой сессии | слайды 7, 11 |
| FR-15 | 3D в браузере | Навигация WebGL/Three.js без нативного клиента | слайды 9, 12 |
| FR-16 | Точки интереса | Карточка объекта, этап процесса, метрики выбранного расчёта, кейс | слайды 9, 10 |
| FR-17 | Экспорт и защита | Выгрузить параметры/результат и пройти воспроизводимую демонстрацию | проверяемость проекта |

## Нефункциональные требования

| ID | Требование | Цель приёмки |
|---|---|---|
| NFR-01 | Переносимость | Документированный запуск на Windows и стандартной среде Node; автономное ядро без сетевых зависимостей |
| NFR-02 | Адаптивность | Основной путь работает при ширине 390, 768 и 1440 px; таблицы прокручиваются без потери управления |
| NFR-03 | Производительность | Один расчёт 84 заявок <1 с; эксперимент 48×12 прогонов <10 с на машине проверки; фактические замеры записать |
| NFR-04 | Доступность | Клавиатурная навигация, названия элементов, различимость состояний без одного только цвета |
| NFR-05 | Устойчивость | Ошибки входов и сохранения не стирают текущие настройки; сообщения понятны пользователю |
| NFR-06 | Безопасность | HTTP-only сессия, серверная проверка доступа, отсутствие секретов в клиентском коде, ограничение размеров входов |
| NFR-07 | Персональные данные | Только условные ID транспорта/пользователей; реальные ФИО/номера не требуются. Это минимизация данных, не заявление о полной сертификации по 152-ФЗ |
| NFR-08 | Честность модели | Синтетика, версия, допущения, формулы, пределы применимости доступны из интерфейса |
| NFR-09 | Отсутствие внешних интеграций | Никаких соединений с ERP, MES, 1С или промышленным оборудованием |
| NFR-10 | Деградация 3D | Если WebGL недоступен, видны схема и точки интереса с теми же данными |
