# Живой терминал: сцена и воспроизведение

Обновление от 9 ноября 2026. Расчётное ядро 1.0.0 и его формулы сохранены. Изменён слой представления результатов и исправлена загрузка расчётного Web Worker в Vinext/Vite.

## Что смотреть

Откройте **3D-тур**. Начальное время — 10:00, когда на базовой смене уже есть машины, налив и очередь. Нажмите воспроизведение: один и тот же календарь меняет положение транспорта, занятость постов, показатели и журнал событий.

- **Базовая очередь**: исходные три поста; виден рост ожидания перед наливом.
- **6 постов + 2 оформления**: повторный расчёт того же спроса с большей мощностью. Это отдельный демонстрационный вариант, не объявленный оптимум.
- **Сбой поста № 1**: базовая мощность с недоступностью 12:00–14:00; сцена открывается внутри сбоя. Пост красный, операция и механизм приостановлены, продукт остаётся зарезервированным. Переместитесь после 14:00, чтобы увидеть продолжение.

Быстрые варианты используют текущий набор данных и seed, заменяя параметры сценария указанными конфигурациями. Точные произвольные изменения остаются на странице «Сценарии». Для короткого импортированного горизонта начало сбоя ограничивается первой третью смены, длительность — одной шестой; вариант остаётся валидным.

## Управление

| Действие | Управление |
|---|---|
| Воспроизведение и пауза | Кнопка слева от шкалы |
| Скорость | 1, 4, 12 или 30 **минут модели в секунду** |
| Точное время | Ползунок; перемотка ставит воспроизведение на паузу |
| Шаг по календарю | Предыдущее / следующее событие, включая границы сбоя |
| Важные моменты | Начало, первый въезд, фактический максимум общей очереди, сбой, конец |
| Повтор смены | Кнопка повтора; без неё воспроизведение заканчивается на горизонте |
| Ракурс | Обзор / налив / резервуары / въезд / план; клавиши 1–5 при фокусе на сцене |
| Вращение / масштаб / сдвиг | Перетаскивание / колесо / правая кнопка; стрелки при фокусе на сцене |
| Инспекция | Нажатие на объект или бензовоз; альтернативно список «Выбрать объект» |
| Сопровождение | «Следовать за машиной» в карточке бензовоза; ручное движение камеры отключает его |
| Видимость | Подписи, кровля эстакады и схема маршрута включаются отдельно |
| Освещение / обзор | День/ночь, облёт и полный экран |
| Низкая мощность устройства | Автовыбор распознаёт программный WebGL; «Экономная» явно отключает тени и ограничивает плотность пикселей |

Тач-навигацию обеспечивает OrbitControls. При `prefers-reduced-motion` переходы между ракурсами мгновенные, автоматический облёт отключён. В скрытой вкладке время не накапливается скачком. У неподвижной сцены нет повторных GPU-отрисовок; невидимая область не рисуется.

## Связь с моделью

| Представление | Источник истины |
|---|---|
| Прибытие, очередь, регистрация, налив, оформление, завершение | `OrderResult`, `Visit`, `orderStateAt()` |
| Общие очереди и отгруженная масса | `snapshotAt()`; никаких самостоятельных счётчиков в 3D |
| Занятый / свободный / резервный / недоступный пост | Число постов, визиты и интервал `Scenario.outage` |
| Прогресс операции | Доля активного времени визита, исключая пересечение со сбоем |
| Шкала резервуара | Начальная масса партий минус `allocations` операций, начавшихся к выбранному времени |
| Свободный допущенный запас | Только уже выпущенные партии минус уже выполненные резервирования |
| Лаборатория | `labStart`, `releasedAt`; будущий выпуск не показывается как состоявшийся |
| Журнал | Только `EventRecord.at <= time` |
| Кейс объекта | Исходные POI и KPI полного рассчитанного прогона, отдельно от состояния выбранного момента |

Положение машины вычисляется **из абсолютного времени**, а не интегрируется от предыдущего кадра. Повторное открытие момента, перемотка назад и разные скорости дают одинаковое положение и статус. Места стоянки назначаются по непересекающимся интервалам ожидания: при выезде одной машины остальные не переставляются.

Маршруты закруглены и параметризованы длиной; ускорение и торможение заданы плавной функцией. Поворот корпуса и вращение колёс следуют траектории. После расчётного завершения машина ещё четыре минуты модели визуально покидает площадку, уже имея статус «Отгружено»; повторного начисления выпуска нет.

**Границы интерпретации:** география, скорости и манёвры условные. Движение укладывается в существующие интервалы ожидания и операций, включая начало подготовки поста; дополнительное транспортное время не добавляется в ядро. Нулевая длительность может давать мгновенный переход. Это не дорожная микросимуляция: разъезды, взаимные блокировки проезжей части и физика сцепки не моделируются. Процент налива — прогресс всей операции, включая подготовку, не датчик жидкости. Насос, трубопроводные маркеры и рукав иллюстрируют состояние операции, не гидравлическую модель и не реальные процедуры управления.

## Архитектура и производительность

- `app/lib/terminal/playback.ts`: чистая временная проекция, маршруты, стабильные места, прогресс, запас и шаги календаря. Не зависит от React, DOM или Three.js.
- `app/lib/terminal/world.ts`: процедурные объекты, материалы, свет и инстансированный автопарк. Статические примитивы объединяются по материалу и ID объекта. Геометрии, текстуры и материалы явно освобождаются.
- `app/lib/terminal/renderer.ts`: камера, выбор объектов лучом, обновление сцены, видимость, режим качества и жизненный цикл WebGL. Модуль загружается динамически только для сцены.
- `app/lib/terminal/pois.ts`: исходные привязки объектов к процессу и кейсам.
- `app/components/terminal-scene.tsx` и `.css`: диспетчерская, инспектор, доступный список объектов, временная шкала, адаптивность и резервный интерфейс.
- `potok-app.tsx`: общий модельный таймер и запуск Worker. Импорт `compute.worker.ts?worker` позволяет Vite формировать корректный HTTP/asset URL и в разработке, и в production. Ошибка создания Worker снимает состояние ожидания и выводит сообщение.

В 3D показываются до **80 одновременно видимых машин** и **12 резервуаров**; при превышении лимита появляется пояснение. Выбранная машина и занятые посты имеют приоритет. Расчёт, показатели и список объектов используют весь результат. Площадка содержит до шести постов; резервные остаются на плане, но не становятся расчётными ресурсами.

Фактическая частота кадров зависит от GPU, разрешения и числа видимых объектов; фиксированный FPS не обещается. Нет внешних моделей, HDR-файлов, CDN или платных ресурсов: все объекты строятся локально из геометрии Three.js.

## Проверки

Из `app/`:

```sh
pnpm test
pnpm typecheck
pnpm build
pnpm exec playwright install chromium
pnpm test:browser
```

Браузерные тесты используют локальные публичные учебные аккаунты. По умолчанию конфигурация запускает `pnpm local --dev` или использует уже работающий адрес 5173. Для проверки собранного приложения запустите его отдельно и передайте URL:

```sh
pnpm start --port 5174
# В другом терминале, POSIX:
POTOK_TEST_URL=http://127.0.0.1:5174 pnpm test:browser
```

В PowerShell: `$env:POTOK_TEST_URL='http://127.0.0.1:5174'; pnpm test:browser`. Для установленного системного Chromium можно задать `POTOK_CHROMIUM_PATH`; иначе используется браузер Playwright. В ограниченной облачной среде Wrangler может потребовать доступный локальный `XDG_CONFIG_HOME`.

`tests/terminal-playback.test.ts` проверяет границы календаря, отсутствие будущих статусов, обратную перемотку, непрерывность маршрутов, уникальные места, запасы, сбой, нулевые ресурсы и пустой спрос. `browser-tests/terminal.spec.ts` проверяет реальный UI и Worker, выбор машины в 3D, управление камерой, окончание/повтор, размеры 1024/768/390, потерю контекста и отсутствие WebGL. Трассы ошибок сохраняются в `app/work/playwright-results/` и не включаются в Git.
