# План проверок

Подробная программа испытаний приведена в разделе 20 [технического задания редакции 1.3](../deliverables/POTOK_TZ_burmalcode78.docx): 25 сценариев с условиями, шагами и ожидаемыми результатами, контрольные входы для точных расчётов и матрицы связи с BR, FR и NFR. Ниже описаны уровни проверок, исполняемые тесты и команды запуска.

## Уровни

1. Аналитические задачи ядра с известным результатом.
2. Инварианты на наборах seeds и конфигураций.
3. Контракты API и сохранение/восстановление.
4. Сквозные пользовательские действия и визуальная приёмка.
5. Репетиция защиты с чистого запуска.

## Уже исполняемые проверки

`app/tests/engine.test.ts`: одиночная заявка; точная очередь двух заявок; общий выпуск партии; исключение двойного расходования запаса; несколько партий; запрет налива до допуска; обрезка по горизонту; масса загруженного, но не выехавшего продукта; завершение на границе; позднее прибытие; нулевая мощность каждого ресурса; пауза/возобновление при сбое; единицы расходов; пустой спрос; повторяемость; отсутствие мутации; привязка случайности к операции; валидация; совместимость; инварианты в серии прогонов; нулевой эффект одинаковых сценариев; интервалы; Парето; запрет повторных seeds.

Команда всего набора: `node --experimental-strip-types --test tests/*.test.ts` из `app/`. На текущем срезе 66 тестов: 31 ядра/экспериментов, 12 API и сохранения/воспроизведения, 3 временной проекции, 1 часов смены, 11 воспроизведения терминала, 8 сравнения/демонстрации/вычислительных заданий. TypeScript и production-сборка проверяются отдельно.

## Инварианты

- Временные отметки событий не убывают.
- Операции одного ресурса не перекрываются.
- Загрузка 0…1 с учётом интервала недоступности.
- Запас и резерв неотрицательны.
- Начальный запас разложен на остаток, резерв, загруженные незавершённые и отгруженные тонны.
- Каждая заявка учтена один раз, включая не прибывшие и незавершённые.
- Начало налива не раньше окончания регистрации и выпуска выделенных партий.
- Совместимость продукта с постом соблюдается.

## Исполняемые проверки API на SQLite

| Сценарий | Ожидаемый результат |
|---|---|
| Запрос без сессии | 401, нет данных |
| Неверный пароль | Понятная ошибка без утечки существования отдельных полей |
| Роль наблюдателя сохраняет сценарий | 403 |
| Некорректный JSON/слишком большой вход | 400/413, текущие записи не повреждены |
| Повторное открытие в новой сессии | Сохранённый сценарий доступен |
| Истёкшая/завершённая сессия | Не принимается сервером |
| Запрос записи с чужого Origin | Отклоняется |
| Ошибка журнала внутри сохранения | Сценарий, расчёт и журнал полностью откатываются |
| Повтор расчёта с сохранённым seed | Все KPI совпадают с записью |
| Иная версия ядра или несовпадение KPI | Повтор не подменяет историческую запись |
| Изменённый JSON исходных данных | Хеш не совпадает, API отвечает 409 |

Адаптер теста исполняет SQL в настоящей SQLite, включая внешние ключи и транзакции. Это проверка обработчика, не браузерный тест и не тест сетевого маршрута. Локальные миграции дополнительно проверены Wrangler: пустая база, повторное применение, принятие уже существующей идентичной схемы и проверка внешних ключей. Сценарий перезапуска приложения включён в проверку пользовательского пути.

## Предстоящие сквозные проверки

Дополнительная нагрузочная проверка CLI: `node --experimental-strip-types scripts/benchmark.ts`. Три набора, включая 2 000 заявок / 300 партий / 100 резервуаров; по три повтора, проверка массы, учёта заявок и загрузки ресурсов. При наличии `before-stock-cache.json` также проверяется равенство SHA-256 полного JSON до/после оптимизации. Отчёт содержит среду и фактические времена, не обещание времени отклика браузера.

- Авторизация, базовая смена, изменение параметра, запуск, сохранение, повторное открытие.
- Парное сравнение и соответствие чисел сырому результату CLI.
- Полный поиск, отображение прогресса и отказ от повторного запуска пока первый не завершён.
- Экспорт/импорт валидного набора; явная ошибка для испорченного.
- 3D-объект открывает данные правильного ID; выбранное время меняет состояние согласованно.
- Мобильная ширина, планшет, desktop; клавиатура и видимый focus.
- Сбой сети при сохранении не стирает сценарий.
- Отсутствие WebGL оставляет схему и доступные точки интереса.
- Подготовленный пример защиты запускается повторно и даёт те же результаты.

Результаты испытаний фиксируются с указанием версии приложения, входных данных и среды выполнения.


## Проверки живого терминала (9 ноября 2026)

Добавлены `app/tests/terminal-playback.test.ts` и шесть сквозных сценариев `app/browser-tests/terminal.spec.ts`. Браузерная проверка использует настоящий локальный API, учебную авторизацию и расчётный Worker, без подмены результатов. Покрыты календарь и перемотка, конец/повтор смены, сбой и восстановление, смена мощности, инспекция запаса, выбор машины лучом в 3D, ракурсы, полный экран, ширины 1024/768/390, потеря контекста и отсутствие WebGL. Команды и границы интерпретации описаны в [terminal-3d.md](terminal-3d.md).

Дополнительные испытания охватывают другие браузеры и измерение FPS на целевых устройствах.

## Общий пользовательский путь

`app/browser-tests/workflow.spec.ts`: 7 сценариев редактирования, сравнения, сохранения и новой сессии, устаревшего результата, поиска, четырёх шагов демонстрации, импорта, ролей и отказа сети. Каталог Playwright содержит 13 сценариев с учётом 3D. Команда запуска из `app`: `pnpm test:browser`.

Сохранность после закрытия БД отдельно подтверждена через API-обработчик и файловую SQLite. `compute-task.test.ts` проверяет соответствие задания расчётам ядра и обмен сообщениями настоящего обработчика Worker через Node worker_threads. Это не проверка загрузки Web Worker браузером.
